# Isolated functional source SDK: witnessed Cell consumer

Status: bounded baseline and delivery plan, not an accepted new capability.
Start from clean accepted canonical `f0e4ba788` (verified PR #696), original
compiler 0.31.141 and Ledger8.1.3. Passport PR #697 is independently reviewed
and awaiting its own complete CI; do not substitute its results for this slice.
Keep at most these two engineering branches active.

## Gap and accepted work

The delivery roadmap requires an external consumer that can implement witnesses,
use ContractLab and prepare a supported proof without paths back to a development
checkout. Existing default bundled functional generation, relocated metadata,
lock validation and Cargo compilation are accepted. Existing functional native,
recorded and selected proof/application cases also remain accepted in their
source-runtime cohorts. This slice does not reopen those capabilities.

A source-first inventory found identical bytes for eleven relevant owners at
accepted `f0e4ba788` and published Passport `c3bb0b37e`. Three selected retained
metadata/proof receipts establish partial qualification, not the exact isolated
witnessed ContractLab/ProofLab closure. This is a bounded evidence comparison,
not a global proof that no equivalent receipt exists. Reuse any exact equivalent
whose complete source/runtime/tool premises remain valid.

The concrete question is whether a default bundled functional SDK and matching
optional testkit sources can execute and prove the maintained witnessed Cell
source from one isolated dependency closure. First establish that baseline;
a failure becomes a retained minimal regression at its actual packaging or
lowering owner. No new compiler option or language primitive is proposed.

## Source and owners

- Preserve the complete maintained
  `tools/compact-rust-backend/tests/functional_effects/field_witness_proof.compact`:
  one Field Cell, typed `private_offset` witness and `apply_offset` export.
- Existing `compactc` target/runtime selection and runtime compatibility owners:
  default bundled `--rust-functional-ledger8`, matching runtime/macros, source
  and generated Program/IR manifests. Registry mode remains refused.
- `testkit-rs` ContractLab, Environment, identity/snapshot and optional ProofLab
  owners. The testkit is unpublished; its source-relative dependencies require
  an explicit qualified source-package recipe. Do not invent registry availability
  or silently introduce another runtime identity.
- Existing functional Field witness proof and official preparation/provider/strict
  transaction helpers: retain actual binding, policy, source and verifier identity.
- A narrow maintained external consumer gate and developer example, only after
  the baseline identifies the missing qualification or actual defect.

## Intended existing public API

Consumers use `functional::apply_offset::Program::new(value)` and its consuming
`execute_native`/`execute_recorded` routes with the generated typed witness trait.
ContractLab uses direct generated-call adapters, explicit Environment and owned
checkpoint semantics. Optional ProofLab supplies the official provider; checking,
proving, verification and strict ledger application remain separate operations.
No builder, runtime type, IR/ABI change or new public facade is intended.
A typed witness does not certify arbitrary callback privacy or external effects.

## Focused baseline and acceptance

1. Recheck the clean accepted source and original packaged compiler. Bind exact
   Scheme/compiler/runtime/macros/ledger/ZKIR/IR/ABI/source identities. Generate
   the complete source into a fresh external directory with default bundled
   runtime. Retain raw generated bytes and all failures; no handwritten SDK
   normalization or source trimming. First run generation and locked Cargo graph
   checks before adding any feature or packaging fix.
2. Qualify one external consumer and optional matching testkit source/package
   closure. Resolve every local manifest inside that closure, with one physical
   runtime identity and exact registry/Git/checksum cohort. No path or symlink may
   lead back into a development checkout. Keep any derived packaging manifest
   explicitly distinct from original source; preserve original bytes and record
   the exact transformation. This is not a fully vendored offline distribution.
3. Implement the real Field witness and compare ordinary native/recorded with
   functional native/recorded outcomes: Cell state, result, private state,
   witness/effect order, errors and replay. Use ContractLab through direct adapters;
   check failure preserves the committed checkpoint and matching snapshot
   identities. External/shared witness effects are not rolled back.
4. Execute the actual documented crate and directly select SDK and consumer for
   strict Clippy. Independently reject a wrong witness return type and reuse of
   a consumed request/context; each has a correct-type positive control and an
   intended compiler diagnostic. Reject malformed untrusted recording/preparation
   before proof or state application; dependency errors cannot count as refusals.
5. For selected `apply_offset`, generate fresh keys and a genuine proof, verify
   with the actual immutable verifier/public binding, and reject changed output,
   binding or verifier as applicable. Separately prove and apply a funded default
   strict transaction, then reject replay. Reuse existing official helpers;
   provider checking alone is not proof or application. No constructor/all-export
   proof or general callback-security claim follows.
6. Retain focused local checks during iteration and complete required CI/proof,
   package/archive and E2E gates for integration. Local arm64 is the development
   platform; Linux runs in GitHub Actions. Normal reconciliation with actually
   accepted Passport/canonical history precedes publication. Use a logical draft
   PR, actual Claude CLI review (Codex fallback only on actual quota), signed
   Conventional/DCO/Assisted-by commits and verified normal merge. Preserve
   ignored/unpublished evidence before post-merge worktree/obsolete-target cleanup.

## Exclusions and stop rules

No Forge, registry/release/shared installation, new CI optimization project,
ledger/profile expansion, source-shape admission, generic test framework, broad
refactor or proof/verdict caching. Do not reopen accepted semantic or metadata
work. Stop dependent work for a real current-parent failure or source drift.
Keep every failed receipt and literal evidence epoch. Update the existing midnight
knowledge base and CAS checkpoint on meaningful progress. The broader Rust AST
and supported-profile handoff remain incomplete after this bounded slice.
