IMPLEMENTATION SEQUENCE

design rationale.

The chapters connect the reason for each change to its implementation and the evidence that followed.

  1. Ledger 8 referenceA stable protocol family and an independent behavioral reference.
  2. Native Rust ASTTyped IR, checked lowering, structured syntax and ordinary Rust execution.
  3. Recorded contractsOrdered effects, replay, installed operations and proof preparation.
  4. Consumer qualificationGenerated APIs, application cohorts and explicit acceptance.
  5. Compositional effectsOperations and ownership replace growing shape catalogues.
  6. Ledger 9 foundationA new SDK graph, ABI 54, Rust 1.99 and funded transactions.
  7. Compatibility workCryptography, wire values, events and the remaining corpus.

Implementation status at the edition cutoff

Ledger 9 foundation merged. PR #725 brought the SDK and toolchain migration into the working branch.

Upstream compatibility continues locally. Selected cryptography, event, serialization and proof results have named arm64 source revisions. Full corpus, native Linux qualification and generated two-contract execution remain open.
